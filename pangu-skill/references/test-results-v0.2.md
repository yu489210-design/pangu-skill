# 盘古 Skill v0.2 人工测试结果

## 测试结论

10 个 v0.2 测试样例全部通过。当前版本验证了专家证据链、高风险节点识别、最小验证闭环、未验证交付级别标注、禁止跳过验证、临时 Skill 升级约束，以及低风险任务不过度验证化。

## 测试环境

* 当前为 instruction-only Skill。
* 测试分支为 `v0.2-expert-evidence-chain`。
* 测试方式为根据 `SKILL.md`、`architecture.md`、`v0.2-plan.md` 和 `test-cases.md` 进行人工模拟。
* 测试过程中未修改 `SKILL.md`。
* 未使用脚本化测试。

## v0.2 核心验证点

1. 专家不能只声明身份，必须建立证据链。
2. 高风险节点必须被识别。
3. 高风险节点不能未验证就批量生成。
4. 用户要求跳过验证时，可以压缩验证范围，但不能删除验证闭环。
5. 未完成验证时，必须标注交付级别。
6. 未验证内容不能伪装成完整交付。
7. 临时 Skill 缺少证据链或验证闭环时，不得升级为正式 Skill。
8. 低风险任务不应被过度验证化。

## 非阻塞观察

1. 医疗科普和 Logo 测试中出现了 WHO、USPTO、WIPO 等依据名称。方向合理，但如果实际运行时没有联网检索或明确引用来源，应避免写得像已经完成正式核验。证据链摘要区分“已核验依据”和“应核验 / 待核验依据”的规则已加入 `SKILL.md` 的 `Output rules`，不再作为待办。
2. v0.2 已明显修复 v0.1 在材质包真实任务中的核心问题：不再未验证弓、低火、剑长、材质清晰度等高风险节点就直接声称完整交付。
3. v0.2 没有把低风险任务过度复杂化。校园推文和读书笔记模板测试均能直接输出用户实例。
4. 当前仍为人工测试结果，不代表已经完成脚本化自动测试。

## 当前版本判断

盘古 Skill v0.2 已完成专家证据链与高风险节点验证规则、10 个 v0.2 人工测试、证据链核验状态微调和最终只读一致性检查；未发现功能或架构阻塞，可进入 `v0.2-candidate` 提交流程。
