# 盘古 Skill v0.2 规划：专家证据链与高风险节点验证

## 一、v0.2 的目标

v0.2 不是推翻 v0.1 的三层结构，而是在第一层增加“专家证据链”和“高风险节点验证”机制。

目标是让领域专家不只是被假定或被扮演，而是必须执行可验证的专家行为：先建立领域参照、验收基准和高风险节点验证，再进入高质量普遍实例生产。

## 二、v0.1 暴露的问题

真实材质包任务中暴露出以下问题：

* 专家身份不等于专家行为。
* 没有建立领域参照基准。
* 没有识别高风险节点。
* 没有先做小样或实机场景验证。
* 生成过程过早进入批量生产。
* 第二层抽象依赖第一层节点质量，如果第一层节点错，第二层也会抽象出错误方法。

在“制作适配网易我的世界 Java 版布吉岛服务器的 PvP 材质包”任务中，Minecraft 物品 PNG 预览不等于第一人称手持渲染结果，尤其是 `bow_pulling_0/1/2` 会受到模型、旋转、缩放和动画影响。程序化生成资源包时，如果没有先建立原版弓、成熟 PvP 材质包或游戏内第一人称效果作为验收基准，就容易把错误方向批量放大。

另一个暴露点是“高清”策略。像素材质不能简单用平滑插值放大；PvP 物品更需要硬边、清晰轮廓和战斗可读性，而不是普通图片式平滑高清。

## 三、v0.2 核心新增机制

新增机制暂定为：专家证据链门槛。

它要求第一层在生产高质量普遍实例之前，必须先完成：

1. 领域参照识别；
2. 验收基准建立；
3. 高风险节点识别；
4. 最小高风险原型验证；
5. 批量生产许可判断。

只有通过这些门槛后，第一层才进入高质量普遍实例生产。

## 四、专家证据链

专家不能只声明自己是专家，而要给出当前项目的证据链。

专家证据链至少包括：

* 该领域必须参考的原版、行业标准、成熟案例或平台规则；
* 当前项目中哪些判断不能凭想象完成；
* 哪些对象必须通过实际场景、渲染环境、运行环境或用户操作来验证；
* 哪些质量标准必须先定义，后生成。

以 Minecraft PvP 材质包为例，专家证据链应包括：

* 原版资源包贴图方向；
* `bow` / `bow_pulling_0` / `bow_pulling_1` / `bow_pulling_2` 的方向基准；
* Java 版第一人称手持模型渲染影响；
* PvP 常见验收点：短剑长度、低火高度、羊毛辨识度、药水辨识度、弓拉满方向、粒子干扰程度；
* 像素材质的硬边规则，避免错误平滑放大。

## 五、高风险节点验证

盘古 Skill 必须先识别高风险节点。

高风险节点是指：

* 一旦错误会显著影响最终体验；
* 不能只靠静态文本或预览判断；
* 会受到平台、渲染、运行环境、用户操作、文件格式、版本兼容或现实约束影响；
* 后续批量生产会放大错误的节点。

高风险节点必须先做最小原型或样张验证，不能直接批量生成。

以 Minecraft PvP 材质包为例：

* 弓朝向必须先单独验证；
* 剑长度和第一人称手感必须先验证；
* 低火高度必须先验证；
* 羊毛和方块可读性必须先验证；
* 物品高清策略必须先验证硬边与清晰度。

## 六、对三层结构的影响

v0.2 不新增第四层，而是强化第一层。

第一层新增前置门槛：

领域造物专家 → 专家证据链 → 高风险节点验证 → 高质量普遍实例生产。

第二层仍然从第一层节点轨迹中抽象方法，但要求节点轨迹必须包含证据链和验证节点。

第三层仍然生成用户实例，但如果用户需求涉及高风险节点，必须保留最小验证闭环，不能为了快速交付而跳过。

## 八、v0.2 测试方向

后续至少覆盖以下测试方向：

1. Minecraft PvP 材质包弓朝向验证；
2. 像素材质硬边 vs 平滑放大验证；
3. 网页工具数据持久化高风险节点验证；
4. 实验报告原始数据缺失时的证据链验证；
5. 需要平台规则或运行环境的项目是否会先建立验收基准。

## 九、v0.2 完成标准

v0.2 完成标准：

* 第一层明确要求专家证据链；
* 第一层明确要求高风险节点识别；
* 高风险节点必须先验证再批量生成；
* 第二层抽象时保留验证节点；
* 第三层不能让用户需求跳过必要验证；
* 新增测试样例能覆盖真实暴露的问题；
* 所有 v0.2 人工测试通过后再标记 v0.2 candidate。
