# 盘古 Skill 测试样例

## 测试目的

本文件用于测试盘古 Skill 的触发范围、三层机制、需求调节、临时 Skill 隐藏规则和最终输出质量。

测试重点不是要求模型展示完整内部过程，而是验证它能否在合适场景中触发盘古 Skill，并默认交付用户真正想要的具体实例。

## 测试原则

* 测试时默认不修改 `SKILL.md`。
* 测试时关注输出行为，不要求暴露完整内部三层过程。
* 盘古 Skill 的默认输出应是用户实例。
* 只有用户明确要求时，才输出压缩方法摘要。
* 测试结果应记录是否触发正确、是否输出具体实例、是否隐藏临时 Skill、是否处理需求缺失或冲突。

## 人工验收标准

* 是否正确触发：应触发的实例制作请求进入盘古路径；普通问答、翻译、简单总结不误触发。
* 是否默认交付具体实例：输出应服务用户要做的对象、作品、产品、内容、工具、资料或项目实例。
* 是否避免暴露完整临时 Skill：默认不展示完整临时 Skill、完整节点轨迹或三层长篇解释。
* 是否在需求过少时使用范式默认和最小追问：能默认补全就默认补全，只问关键缺口。
* 是否在需求冲突时进行分层和主线收束：识别硬约束、核心偏好、弱偏好，并处理冲突。
* 是否保留产品必要骨架：个性化需求不能删除该类产品成型所必需的核心方法链。
* 是否输出最小可执行下一步：结尾应给出一个清楚、可执行的下一步动作。
