# 盘古 Skill 架构冻结文档

## 总定位

盘古 Skill 是一个范式驱动的个性化实例生成系统。用户调用它时，目的不是制作 Skill，而是制作一个属于自己的具体实例。Skill 生成只是盘古内部的中间过程。

总路径是：

用户提出想制作的对象
→ 第一层生成高质量普遍实例
→ 第二层从制作过程抽象出临时专用 Skill
→ 第三层调用临时专用 Skill 生成用户个性化实例
→ 处理临时 Skill

## 第一层：高质量范式实例生产层

第一层的目标不是列流程，也不是生成 Skill，而是让一个与目标对象高度匹配的领域造物专家，通过关键节点式交互，从 0 到 1 做出一个高质量的普遍实例。

v0.2 后，第一层必须先通过前置门槛：生成领域造物专家 → 建立专家证据链 → 识别高风险节点 → 对高风险节点进行最小原型或样张验证 → 生产高质量普遍实例。

专家不是泛泛的“某领域专家”，而是能抓住项目关键制作节点的领域造物专家。专家最重要的能力是知道一个项目从想法到成品过程中，哪些节点真正决定质量、结构和交付结果。

领域造物专家不能只声明自己是专家，而要建立当前项目的专家证据链。专家证据链至少包括：

* 该领域必须参考的原版、行业标准、成熟案例或平台规则；
* 当前项目中哪些判断不能凭想象完成；
* 哪些对象必须通过实际场景、渲染环境、运行环境或用户操作来验证；
* 哪些质量标准必须先定义，后生成。

关键节点不是普通步骤，而是会改变项目状态、影响后续质量、决定最终交付形态的制作决策点。

高风险节点是指：一旦错误会显著影响最终体验，不能只靠静态文本或预览判断，会受到平台、渲染、运行环境、用户操作、文件格式、版本兼容或现实约束影响，并且后续批量生产会放大错误的节点。高风险节点必须先做最小原型、样张、局部验证或场景验证，不能直接批量生成。

制作 Minecraft PvP 材质包时，弓朝向、`bow_pulling_0/1/2`、第一人称手持效果、短剑长度、低火高度、羊毛辨识度、药水辨识度、像素材质硬边规则都属于需要参照或验证的高风险内容，不能只看 PNG 预览或直接平滑放大。

专家在制作高质量普遍实例时，不得先机械列出完整节点再开始生产。核心节点必须在真实制作推进过程中自然产生。每一次与 AI 的交互，都必须发生在当前关键制作节点上，并直接推动产品进入下一个成型状态。

每次节点交互必须短、准、必要，只解决一个关键问题，不闲聊，不长篇解释，不问低影响偏好。交互完成后，专家必须验收并固化当前节点成果。

第一层结束时，必须产出：

1. 一个高质量普遍实例；
2. 一条关键节点交互轨迹。

## 第二层：炼法成 Skill 层

第二层的目标是把第一层真实制作高质量产品时留下的关键节点交互过程，抽象成一个可以反复生成同类产品实例的临时专用 Skill。

核心路径是：

节点交互过程
→ 节点方法
→ 方法链
→ 临时专用 Skill

第二层首先把第一层中的每一次关键节点交互，转化为一个可复用的实例化方法。

每个节点方法必须包含：

* 方法名；
* 来源节点；
* 适用场景；
* 输入信息；
* 处理动作；
* 输出结果；
* 默认策略；
* 质量标准；
* 后续影响。

然后，第二层根据第一层真实制作过程中的顺序、依赖关系和质量约束，把节点方法串联成一条完整的方法链。

第二层从第一层抽象方法时，不仅要抽象生产节点，也要抽象证据链节点和验证节点。否则如果第一层节点错误，第二层会把错误方法固化成临时专用 Skill。

Skill 中的核心方法必须尽量能追溯到第一层的某个关键节点，这叫节点可追溯性。

第二层要保留第一层的造物逻辑，而不是保留第一层的具体内容。第一层的具体风格、参数和内容要被参数化，不能把某个具体样品锁死成唯一模式。

第二层最终产出的是一个针对当前对象类别的临时专用 Skill。

## 第三层：用户实例生成层

第三层的目标是调用第二层生成的临时专用 Skill，根据用户需求制作用户真正想要的具体实例。

第三层需要先把用户的大白话需求转化为专用 Skill 可以执行的参数。

用户需求可能过少，也可能过多。

当用户需求过少时，使用范式默认和最小追问。能默认就默认，默认值必须来自第二层 Skill 中的高质量范式。只有缺失信息会严重影响最终方向、结构、质量或交付时，才提出最少量关键问题。

当用户需求适中时，第三层应直接将用户需求映射为临时专用 Skill 可执行的参数，并调用方法链生成实例，不需要额外追问或重新规划流程。

当用户需求过多时，进行需求分层、冲突检测和主线收束。

需求分为：

1. 硬约束：必须满足；
2. 核心偏好：优先满足，决定主方向；
3. 弱偏好：能加就加，不能加就转化为局部元素或可选项。

如果需求之间冲突，不能机械照单全收，必须明确主次关系并压缩成一个清晰主线。

第三层必须区分可变参数和不可变骨架。用户需求可以改变风格、用途、平台、预算、复杂度、输出形式等参数，但不能破坏该类产品成型所必需的核心方法链。

如果用户需求涉及高风险节点，第三层不能为了快速交付而跳过必要验证。用户需求只能影响参数和范围，不能删除该类项目必要的验证闭环。

第三层结束时，输出的是用户真正想要的具体实例，而不是临时 Skill 文档。

## 临时 Skill 处理规则

三层走完后，第二层生成的临时 Skill 默认是内部中间产物。

它不默认展示给用户，也不默认永久保存。

默认处理方式是即用即弃，只保留一份压缩方法摘要，用于本轮继续迭代。

如果用户继续要求修改、扩展或生成同类变体，临时 Skill 可以在当前任务中短期保留。

如果用户询问生成逻辑，可以输出压缩方法摘要，而不是完整临时 Skill。

只有在以下条件同时满足时，临时 Skill 才能升级为正式专用 Skill：

1. 用户明确表示以后还想反复使用；
2. 临时 Skill 的方法链完整；
3. 它已经成功生成了可用实例；
4. 质量检查标准清楚；
5. 它不只适用于当前实例，而能适用于同类多个实例。

临时 Skill 若缺少证据链或高风险节点验证，不应升级为正式专用 Skill。

升级必须经过用户确认。

盘古 Skill 本体只保留三层造物机制，不能被临时 Skill 污染。
